What it does

Turn a messy project folder into a structured build attempt.

AutoBuild analyzes the project before acting. It uses the files, manifests, dependency declarations, build systems, and tests that actually exist in the target project rather than assuming every project uses the same stack.

01 / Scan

Inspect the project.

Discover project structure, manifests, source trees, dependencies, build tools, and runnable components.

02 / Understand

Determine the build path.

Identify the project technologies and the order in which supported components need to be prepared.

03 / Repair

Address build blockers.

Repair supported dependency and build issues when AutoBuild has enough evidence to do so.

04 / Build

Run the real build.

Use the project's actual tools and build commands rather than reporting success without execution.

05 / Test

Check the result.

Run supported project tests and verification steps so a build failure stays visible instead of being labeled complete.

06 / Launch

Help reach a runnable state.

When the project exposes a supported launch path, AutoBuild can help start the successfully built result.
